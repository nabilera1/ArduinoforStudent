## GitHub와 위키독스 게시 안내

확인 기준일: 2026-11-10. 이 폴더는 업로드용 원고이며 아직 온라인 게시한 상태가 아닙니다.

### 공식 규칙을 반영한 구조

README.md 첫 H1은 책 제목입니다. TOC.md가 장과 하위 페이지를 연결합니다. 본문 pages의 헤딩은 H2부터 시작합니다. 위키독스는 전자책 생성 시 H1을 챕터로 인식하므로 본문 H1을 권장하지 않습니다. 제목 수준은 글자 크기를 위해 건너뛰지 않습니다.

TOC 항목은 번호를 붙여 정렬 순서를 고정합니다. 하위 페이지는 공백 2칸 단위로 들여씁니다. 이미지 파일은 assets의 영문 파일명 PNG로 저장하고 원고에서 상대 경로로 참조합니다. 일반 파일인 코드와 PPT는 이미지처럼 자동 업로드되지 않으므로 외부 GitHub 링크를 사용해야 합니다.

출처: [위키독스 제목 작성 주의사항](https://wikidocs.net/141880), [GitHub로 책 만들기](https://wikidocs.net/321336), [저장소 구성](https://wikidocs.net/346510).

### 게시 순서

1. 저자명, 저장소 이름, 공개 범위, 자료와 코드의 라이선스를 결정합니다. 현재 LICENSE는 확정하지 않았습니다.
2. 위키독스에서 계정설정 > 나의 책 > 깃허브 책 만들기를 선택합니다. 제목은 ‘중고등학생을 위한 아두이노 입문’입니다.
3. 신규 저장소 또는 기존 저장소 연결 방식을 선택하고 본인 계정으로 GitHub 권한을 확인합니다. 기존 위키독스 일반 책을 연결하는 것과 기존 GitHub 저장소를 연결하는 것은 다른 작업입니다.
4. 생성되거나 연결된 저장소의 원본을 보존하고 이 폴더 내용을 검토하여 반영합니다. 자동 생성된 설정 파일을 무조건 지우지 않습니다.
5. 저장소 주소가 정해지면 아래 스크립트로 코드·PPT 링크를 GitHub 절대 주소로 변환합니다. 교재 내부 MD와 이미지 링크는 유지합니다.

```powershell
py tools/configure_repository.py --repo https://github.com/사용자/저장소 --branch main
py tools/validate.py
```

6. git diff로 내용과 공개할 파일을 확인하고 commit, push합니다. 저장소의 코드 화면에서 Raw 또는 다운로드 버튼으로 원본 파일을 받을 수 있습니다.
7. 위키독스에서 목차, 첫 장, 이미지, 코드 블록, 코드와 PPT 링크를 직접 확인합니다. 필요하면 책 수정 > 깃허브 > 지금 동기화를 사용합니다.

### 게시 전 확인할 항목

- 목차에 연결된 원고가 실제로 있고 대소문자가 일치하는가?
- README 첫 줄 제목이 정확한가? 본문에 의도하지 않은 H1이 없는가?
- PNG 이미지가 보이고 링크의 파일을 익명 브라우저에서도 받을 수 있는가?
- 공개 저장소에서 정답도 노출된다는 사실을 평가 설계에 반영했는가?
- 학생 개인정보·토큰·학교 내부 정보가 없는가?
- 수정한 코드가 실제 키트에서 동작하는지 확인하고 보드·센서 모델을 기록했는가?

위키독스의 상대 MD 링크가 실제 페이지 링크로 어떻게 표시되는지는 연결 후 확인해야 합니다. 코드·PPT 외부 링크의 실동작 역시 실제 저장소 주소가 있어야 검증할 수 있습니다. 현재 자료는 플랫폼 계정 연결이나 공개 사이트 개설을 완료한 것으로 간주하지 않습니다.
